# Talotrace Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Talotrace interview-scoring backend as a single FastAPI monolith in `talot-backend`, copied from the `virtual-facility` template with `database` + `iam` libraries kept and all messaging parts dropped.

**Architecture:** A `uv` workspace with `libs/database`, `libs/iam`, and `apps/api`. The app is hexagonal per feature module (`auth`, `catalog`, `candidates`, `scoring`, `importing`, `health`), each with `domain` / `application` / `infrastructure` / `presentation` layers. Scoring runs as an in-process `asyncio` worker pool draining `scoring_jobs` via `SELECT ... FOR UPDATE SKIP LOCKED`.

**Tech Stack:** Python 3.14, FastAPI `>=0.135,<1.0`, Pydantic v2, SQLAlchemy 2.0 async + asyncpg (aiosqlite for SQL tests), Alembic, PostgreSQL 18, `httpx` for the DeepSeek client, `uv` workspace.

**Spec:** `docs/superpowers/specs/2026-10-18-backend-design.md` (implements `docs/superpowers/specs/2026-10-18-api-contract-design.md`). The plan argues from both; read them together.

## Global Constraints

- Python `>=3.14`; FastAPI `>=0.135,<1.0`; PostgreSQL 18; run everything through `uv run` from `talot-backend/`.
- RFC 7807 error shape everywhere: `{"type": "about:blank", "title": ..., "status": ..., "detail": ...}`.
- `Role` enum values: `admin`, `regular`, and `hr` (the new one). HR endpoints require `require_roles(Role.HR)`.
- Candidate auth is `X-Candidate-Token` header resolved to a `Candidate`; token value is `secrets.token_urlsafe(32)`.
- No URL version prefix; paths are `/auth`, `/candidate`, `/hr`, `/health`.
- Scores are integers 1..4. `content_hash` is lowercase SHA-256 hex of the submitted bytes (UTF-8 text, or raw audio bytes).
- Config env names (exact): `database_url`, `candidate_web_origin`, `cors_origins`, `scoring_workers`, `scoring_max_attempts`, `scoring_lease_timeout_seconds`, `deepseek_api_key`, `deepseek_model`, `deepseek_base_url`, `audio_storage_dir`, `seed_hr_email`, `seed_hr_password`, plus inherited `jwt_secret`, `jwt_algorithm`, `jwt_access_token_ttl_seconds`, `jwt_refresh_token_ttl_seconds`.
- No em dashes in docs/strings; commit messages must not carry an agent co-author trailer.

## Review Focus

1. **Byte-identical resubmission must not re-score** - the upsert's `WHERE content_hash <> excluded.content_hash` must make a no-op return `changed=False` with no job reset. (Task 6, 7)
2. **Changed resubmission must bump `version` and re-queue the job** - same content path, different hash. (Task 6, 7)
3. **A failed job is never shown as a score** - `final_score` stays null on `failed`. (Task 9, 11)
4. **Score override requires a non-empty reason and a 1..4 integer, and only on `scored`/`needs_a_person`** - everything else is `422`/`409`. (Task 11, 12)
5. **Candidate isolation** - candidate endpoints never return another candidate's data, scores, or grading guides. (Task 8)
6. **Import idempotency** - re-importing the same pack must not duplicate questions, candidates, or answers. (Task 13)
7. **Prompt injection** - an answer that instructs the model cannot change its own stored score; output is schema-validated. (Task 10, 11)

Each line above is pinned to a task with its own test in that task's steps.
